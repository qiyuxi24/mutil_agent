# Skill: handoff（交接文档）

把当前会话压成一份交接文档，让一个**全新上下文的 Agent** 能继续干。**复用我们已有的 @mention + 里程碑机制，把「只发一个里程碑词」升级为「发一份能接手的上下文」**。

## 执行步骤

1. **收口当前产出**：确认本环节里程碑产物已落盘（`shared/tasks/{id}/` 下对应文件）。
2. **写交接文档**（写到 `shared/tasks/{id}/handoff.md`），包含：
   - **目标**：本次任务要交付什么、进度到哪。
   - **已完成**：本环节做了什么、关键决策与原因。
   - **待办**：下一环节要做什么、明确的下一步动作。
   - **阻塞/风险**：哪些没解决、为什么、可能影响什么。
   - **建议 skills**：下一 Agent 应该挂/用哪些 skill（如「下一步修 bug，建议用 `code-gen` + `tdd`」）。
3. **引用不复制**：不要复制已在其他产物里的内容（spec/root-cause/fix/ADR/issue/commit/diff），**按路径引用**它们。
4. **脱敏**：去掉 API key、密码、PII 等敏感信息。
5. **交棒**：@mention 下一 Agent（完整 Matrix ID）+ 发送里程碑词，附交接文档路径。

## 输出

- `shared/tasks/{id}/handoff.md` + 里程碑交接（如 `FIX_APPLIED` + @下一棒）。

## Gotchas

- **交接文档 ≠ 复盘报告**：它面向「接手的人」，只讲「接下来怎么继续」；复盘（经验沉淀）交给 `retrospective`。
- **噪音 @mention 会死循环**：只 @mention 真正要接手的人，不发「收到/谢谢」。

## 失败处理

- 下一棒长期未响应 → 由 Manager 的调度 loop 兜底（超时重派），本 skill 只保证交接文档完整可接手。

## 安全边界

- 交接文档脱敏后落盘；不把凭据写进文档。
