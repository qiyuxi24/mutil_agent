# Skill: code-review（双轴评审）

评审「固定点 → HEAD」之间的 diff，两根轴：

- **Standards**：代码是否符合本仓库**成文的编码规范**？
- **Spec**：代码是否**忠实实现**了原始 issue / spec？

两轴**并行子代理**跑，互不污染上下文，本 skill 只聚合结论。

## 流程

### 1. 钉住固定点
固定点是用户给的那条（commit SHA / 分支 / tag / main / HEAD~5…）。没给就追问。用 `git diff <固定点>...HEAD`（三点，对比 merge-base）抓 diff，`git log <固定点>..HEAD --oneline` 记提交。**先确认固定点能 resolve 且 diff 非空**，坏引用/空 diff 在这里就失败，别让它在两个子代理里炸。

### 2. 找 spec 来源
按序找：commit message 里的 issue 引用（`#123`/`Closes #45`）→ 用户传的路径 → `docs/` `specs/` `.scratch/` 下匹配分支/特性的 spec 文件 → 都没有则问用户。用户说没有，Spec 轴跳过并报「无 spec」。

### 3. 找规范来源
仓库里任何成文规范（`CODING_STANDARDS.md`/`CONTRIBUTING.md` 等）。**此外 Standards 轴永远携带下面的「坏味道基线」**——固定的一组 Fowler 坏味道（《重构》第 3 章），仓库啥都没写也适用。两条约束：**仓库成文规范优先**（它认可的就压掉基线告警）；**永远是判断**（每个味道是带标签的启发式，不是硬违规，工具已强制管的跳过）。

坏味道基线（每个读「是什么→怎么修」，对 diff 逐条比对）：
- **神秘命名**：函数/变量/类型名看不出它做什么 → 改名。
- **重复代码**：同一逻辑形状在多处 → 抽出共享形状，两处调用。
- **依恋情结**：方法动别人的数据多于自己的 → 移到它依恋的数据上。
- **数据泥团**：同几个字段总一起出现 → 打包成一个类型。
- **基本类型偏执**：用原始类型/字符串顶一个该有专属类型的领域概念 → 给它一个小类型。
- **重复 switch**：同一类型上同样的 switch 反复出现 → 多态，或一处 map 共享。
- **霰弹式修改**：一个逻辑改动逼得散改多文件 → 把一起变的东西聚到一个模块。
- **发散式变化**：一个文件为多个无关理由被改 → 拆，每个模块只为一个理由变。
- **投机性通用**：为 spec 没有的需求加的抽象/参数/钩子 → 删，inline 回去直到真实需求出现。
- **消息链**：`a.b().c().d()` 长链 → 在第一个对象上藏一个方法。
- **中间人**：一个类/函数大多只是转发 → 砍掉，直接调真实目标。
- **拒绝馈赠**：子类忽略/覆盖大部分继承 → 去继承，用组合。

### 4. 并行派两个子代理
- **Standards 子代理**：给全 diff 命令 + 提交清单 + 步骤 3 找到的规范源 + 完整坏味道基线。任务：「逐文件/逐 hunk 报告 (a) 每处违反成文规范的地方（引用规范文件+条目）；(b) 发现的基线坏味道（点名+引用 hunk）。区分硬违规与判断——成文规范可硬，基线味道永远是判断，成文规范覆盖基线。跳过工具已强制管的。400 字内。」
- **Spec 子代理**：给 diff + spec 内容。任务：「报告 (a) spec 要求但缺失/不全；(b) diff 里 spec 没要的行为（范围蔓延）；(c) 看似实现但实现有误。每条引用 spec 原文。400 字内。」无 spec 则跳过此轴。

### 5. 聚合
把两份报告放 `## Standards` / `## Spec` 两个标题下，原样或轻清理。**不要合并或重排**——两轴刻意分离。结尾一句话：每轴各多少条、每轴内部最严重的问题（若有）。**不跨轴选冠军**——这正是分离要防止的重排。

## 为什么两轴

一个改动可能过一轴挂另一轴：代码全合规范但实现了错的东西 = Standards 过、Spec 挂；代码完全按 issue 做但破坏项目约定 = Spec 过、Standards 挂。**分开报，才不会被一根轴掩盖另一根。**

## 输出

- 双轴评审报告，落 `shared/tasks/{id}/` 并复用 `evidence-log`；结论作为「审批闸门」输入（配合 `release-gate`）。

## 失败处理

- 固定点解析失败/空 diff → 直接失败并提示，不派子代理。
- 规范源缺失 → 仍跑坏味道基线，标注「仓库无成文规范，仅基线」。

## 安全边界

- 只读 diff 与规范；不改代码；评审结论可溯源到具体文件/行。
