# Skill: context-hygiene（上下文卫生）

**限制 Agent 的从来不是智商，是注意力预算。** 本 skill 把 `references/theory/CONTEXT-ENGINEERING.md` 的理论固化为个体 Agent 的操作纪律：窗口保持短，用外部存储 + 按需检索补。

## 核心策略

1. **信息卸载（Offloading）**：不把所有信息塞上下文。工具输出的**完整版写外部文件**（`shared/tasks/{id}/`，占 0 token），上下文只留精简引用（路径，10-50 token/条）。整体可省约 85% token。
2. **压缩（Compaction）**：长历史用高保真摘要替代。**先优化召回再优化精度**（别漏关键信息）。压缩方向**永远从尾部开始、不碰头部**（保护 cache prefix）。
3. **渐进披露（Progressive Disclosure）**：维护轻量引用（路径/查询），运行时按需加载，不预加载全部。用 `code-search`/grep 即时探索，而非全量读入。工作记忆里只留「当前必要子集」。
4. **注意力操纵（Attention）**：利用 **Lost in the Middle**（中间易忘、两端受关注），关键任务/待办放上下文**开头或结尾**，关键信息标「高保留优先级」。

## 执行步骤

1. **定预算**：按窗口设 token 预算——system prompt + 工具 10-15%、工作记忆 30-40%、按需检索 20-30%、工具结果 + 当前任务 20-30%、输出缓冲 15-25%。
2. **先卸载**：接到大产物（长日志/大 diff/全量报告）先落盘 `shared/tasks/{id}/`，只把路径 + 摘要放上下文。
3. **按需读**：用 `code-search`/`repo-context` 定位到具体文件/行再读，不整仓读入。
4. **适时压缩**：上下文使用率达 70-75% 触发轻压缩，85-90% 强制压缩；工具结果只保留最近 5-10 轮完整输出。
5. **子代理分流**：深度探索（大范围搜索/长测试/全量分析）派给子代理，返回 1000-2000 token 浓缩结论，主上下文只做判断。

## 输出

- 精简后的工作上下文 + 落盘的外部产物引用清单。

## Gotchas

- **信息放进去 ≠ 模型能看到**：窗口越大注意力越分散（32k 召回率已降至约 78%，100k 关键信息「视而不见」概率升至 30%）。精简是常态，扩展是例外。
- **单任务聚焦**（呼应 Ralph）：一次只处理一个原子任务，上下文被「当前小任务」占据，而非整个项目。
- **System prompt 保持静态**：最大化 cache 命中，动态内容（历史/工具结果）放固定前缀之后。

## 失败处理

- 上下文仍濒临溢出 → 强制压缩 + 把最不重要任务移出上下文到外部 TODO 文件，只留指针。

## 安全边界

- 卸载到外部文件的内容同样受权限约束；压缩不丢失关键决策/未解决错误/实现细节。
